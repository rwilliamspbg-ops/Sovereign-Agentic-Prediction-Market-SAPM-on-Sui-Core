# Formal Proof Obligations (mapping to implementation)

This document lists the remaining formal obligations, maps them to code
locations, and describes the expected proof approach and priority.

1) KEM correctness (High priority)
   - Obligation: For every Kyber public key generated by the implementation,
     the implementation `Decapsulate` of the produced ciphertext recovers the
     same shared secret as produced by `Encapsulate`.
   - Code: `crypto/pqc_kex.go` — `Encapsulate`, `Decapsulate`.
   - Lean mapping: `bridging.impl_encapsulate` / `bridging.impl_decapsulate`
   - Proof approach: Use `kem_api.KEM_correctness` as an axiom or derive from
     concrete CIRCL Kyber properties. Marked as required for `kem_correctness`.

2) Hybrid KEX consistency & serialization (High)
   - Obligation: `ExportPublic()` serialization must match the format assumed in
     proofs (classical(32) || kyber.PublicKey bytes) and `Encapsulate`/`Decapsulate`
     must accept that serialization.
   - Code: `crypto/pqc_kex.go` — `ExportPublic`.
   - Proof approach: Provide a deterministic serialization lemma; prove that
     `ExportPublic` returns the same byte layout used in proofs.

3) HKDF-derived key equivalence (Medium)
   - Obligation: HKDF expansion used in `DeriveSessionKeys` must be deterministic
     and both sides derive identical keys when given the same shared secret.
   - Code: `crypto/pqc_kex.go` — `DeriveSymmetricKey`, `DeriveSessionKeys`.
   - Proof approach: Model HKDF as a deterministic function in Lean and prove
     equality based on identical inputs.

4) TPM PCR verification & attestation binding (High)
   - Obligation: `attestation/tpm_client.go` reads PCRs and `GenerateAttestationReport`
     produces a report that, when verified, implies `TrustedPlatform` in Lean.
   - Code: `attestation/tpm_client.go` and `formal_verification/lean4/crypto/tpm_primitives.lean`.
   - Proof approach: Formalize PCR model, define `verifyPCRDigests` semantics,
     and show `tpm_attestation_verification` holds when the implementation's
     verification returns true.

5) End-to-end protocol transcript binding (Medium)
   - Obligation: The full handshake transcript used to derive HKDF salt and
     info must be well-defined and included in the key derivation to prevent
     cross-protocol attacks.
   - Code: `crypto/pqc_kex.go`, CLI `cmd/kexcli/main.go`.
   - Proof approach: Define transcript model and show key derivation includes
     sufficient context (infoBase, optional salt).

6) Integration tests and proof artifacts (Low)
   - Obligation: Automate running Lean checks and publish proof artifacts as
     part of CI.
   - Task: Add `lakefile`/Lean project config and CI job to run proofs.
